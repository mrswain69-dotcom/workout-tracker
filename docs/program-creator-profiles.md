# Creator profiles and credential review

Plans → Program Library → My creator profile lets the current profile publish a separate creator biography. It includes display name, profile picture, headline, biography, experience description and years, creator category, specialisms, tags, website and qualification statements (name, awarding body, optional HTTPS register/reference).

Creator bios are optional and explicitly published to signed-in Community members. A creator’s family retains control through existing profile/PIN authorisation. Community programme cards and previews link to the published bio, which includes the creator’s available Community programmes. Creator names, specialisms and tags are searchable; the catalogue also filters by creator specialism. Copy creator bio link creates a shareable `?creator=<profile-id>` URL that opens the biography after sign-in. Unpublishing hides it and its programme attribution without removing adopted programmes.

Qualifications and experience are self-declared by default. A verified mark means identity and the listed qualifications were reviewed, with the date and review scope shown on the bio; it is not a certification of each programme or a guarantee of suitability. A programme’s old `credentials_verified` field no longer supplies Community badges. The badge is derived from its creator’s current reviewed credential revision, independently of programme access/pricing.

Verification requests carry an immutable snapshot of the name, creator category and qualifications, an explanation and up to ten private evidence files. PDF/JPEG/PNG files are limited to 5 MB each. Profile photos are JPEG/PNG/WebP, limited to 3 MB. Both buckets are private: published profile photos are readable by signed-in viewers, but evidence is restricted to the creator’s family and nominated reviewers. File views use ten-minute signed URLs. Uploaded files remain private when unused; removing a photo from a profile removes its public discoverability. Existing issued signed URLs expire within ten minutes.

Requests have pending, approved, changes requested, rejected, superseded and revoked statuses. Only nominated reviewers can read the review queue and approve, request evidence, reject or revoke a mark. They must explain the checks; approval summaries are public and must not include private document IDs. Reviewers cannot approve their own family’s profiles. Changing the creator name, category or listed qualifications removes verification, increments the credential revision and supersedes earlier pending/approved requests; bio/experience edits preserve reviewed credentials. The creator must save current details before submitting. A replacement request can be made after requested changes or rejection. Review access and badge fields cannot be granted or set by the creator.
