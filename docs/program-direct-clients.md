# Direct coach–client connections

Plans → Program Library → Coaching connections provides individual coaching outside teams. Coach tools creates an invitation for the active coach profile and a coach-supplied display name. Copy its link and share it with one intended client. Invitations expire after 7, 14 or 30 days and can be used only once. There can be at most 50 pending, unexpired invitations per coach account.

The invitation URL lands in Coaching connections after sign-in. A recipient can also paste its link or UUID code. Preview exposes only the coach’s display name and expiry to a signed-in token holder; it does not expose a recipient, email or family directory. Acceptance explicitly identifies the selected recipient profile, shares its name with the coach and allows future programme offers. Profiles in the coach’s own account use existing personal-plan workflows. Duplicate active connections between the same coach and client profile are rejected.

My coaches lists connections for the selected recipient profile. Coach tools lists the account’s clients and unused invitations. Refresh connections retrieves newly accepted clients. Either account can end a connection; coaches can also revoke an unused invitation. Both sides receive in-app connected/disconnected notifications. Their inbox entries open Coaching connections.

My Programs → View details → Assign programme now offers Team members or Direct clients. One or several connected clients can receive the current frozen version with an optional note, start date, completion mode and existing follow/edit/copy permissions. Up to 200 recipients can be selected in one server call. An invitation is distinct from adopting a programme: nothing is added to a client’s plan until they preview and accept its assignment in Shared & assigned. The existing base-plus-one-add-on limit, replacement, task retention and undo remain unchanged.

Assignments sent includes consented client names, status and existing revoke/reschedule/update controls. Version replacement and reschedule offers inherit their original client connection. Coach reports can filter Direct clients. Connecting alone enables no workout or Assessment reporting: recipients opt in separately per programme and can withdraw consent later.

Disconnect withdraws every pending direct assignment linked to that connection, including update offers, and immediately denies further coach reporting and management through it. Accepted programme content, logs, XP, checkpoints, recipient controls and undo remain. Reconnecting requires a fresh invitation; it never restores old reporting access. A separate team membership can still allow team assignments under that membership’s independent permissions.

Security: participant-scoped SELECT-only RLS; owner-checked mutation RPCs with fixed empty search paths; no anonymous execution; active connection IDs required for cross-account direct assignment inserts. Foreign profile data is never read to populate coach lists. Single-use acceptance uses a row lock, uniqueness prevents duplicate active pairs, and assignment creation locks connections against disconnect. Expired/revoked invitations cannot be accepted. Connection deletion clears assignment references while retaining accepted programme history; inaccessible foreign assignments cannot be managed without an active connection.

Verification: rollback-only two-account SQL tests cover invitation preview/acceptance, recipient profile isolation, foreign token RLS, anonymous/write privilege denial, unconnected and wrong-profile assignment rejection, duplicate pending prevention, follow permissions, opt-in reporting, update inheritance, expiry, disconnect and retained plans. Existing team-assignment, coaching and programme-management SQL suites are included. UI/API tests cover explicit consent, denied authorization, expired and stale previews, link creation, disconnect cancellation and assigning a direct client without a team.
