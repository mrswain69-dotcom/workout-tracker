## Shared design rules

- One male and one female version at every tier; one unlock earns both. Awards, equipment quality, material finish and presentation have equal value for both versions. No additional claim, session requirement or XP for switching.
- Keep a recognisable fictional male athlete and a recognisable fictional female athlete through each sport's ladder. Stable face/hair/skin identity within that ladder, with gentle junior-to-adult development. Different sports use different characters. Do not use real athlete likenesses.
- Bronze is visibly a youth/developing athlete, around 12–14, in basic practical kit; Silver is older academy stage, around 15–17. Gold is young adult; Platinum onward is established adult. This is the character's story, not an estimate of the user's age or ability. Higher tiers do not mean exaggerated muscles, sexualisation or compulsory body growth.
- Premium semi-realistic stylised 3D game-skin finish, credible for ages 10 through adult. Natural body proportions, crisp face, clean silhouette and believable equipment. Avoid childish/chibi presentation.
- Prestige grows through kit, relevant accessories, individual recognition, club/league/international awards and finally formal presentation. Changing colour or adding glow is not sufficient progression.
- Both variants have functional sport clothing and equally substantial awards. Formal female portraits use a tailored trouser suit, with the same visual stature as the male suit; no default high heels or evening dress.
- Bronze has no award. Later trophy collections have at most three large recognition objects; the athlete remains dominant. Small watch/medal/ring details support the story rather than replacing a visible tier upgrade.
- Full-body square portraits through Champion, with entire head, hands, equipment and feet visible. Unreal uses a deliberate head-to-mid-thigh awards-night portrait, matching the existing football finish. Keep 6–8% clear transparent margins and trophies fully inside the canvas.
- At Unreal, omit playing/training equipment: the formal athlete and final honour are the focus. Do not add a bat, racket, mat or machine just because it appears in earlier tiers.
- Real transparent PNG alpha, not a black/white background or a painted checkerboard. At least 512 × 512, square, clean edges; inspect actual output dimensions rather than assuming the generator followed a requested size. Preserve alpha on any later web export.
- No embedded words, numbers, inscriptions, brand/team logos, borders or watermarks. Original unbranded trophy designs can evoke football boots, rugby balls, cups, medals and other sport motifs. No need to reproduce licensed trophy engravings or team crests.
- Awards are fictional visual symbols of the Workout Tracker character's progression. The user's actual unlock is counted sessions, not a claim to have won a real competition, earned a belt or obtained a professional qualification.
- Inspect local reference images before using them. Identify their role as style/character/progression references. Create one finished portrait per image-generation call; no combined male/female sheet or eight-character contact sheet as production assets.

## Prompt production without repeated planning

The canonical source is `docs/avatar-production/paired-sport-avatar-briefs.json`. It contains the shared prompt, character anchors, stage rules and all 104 paired tier briefs. The prompt helper combines these into 208 individual male/female prompts.

Print one prompt:

```bash
python scripts/sport_avatar_prompt.py --sport football --tier bronze --variant female
```

List the complete target asset inventory without generating images:

```bash
python scripts/sport_avatar_prompt.py --manifest
```

Use the resulting prompt with the built-in image-generation tool, together with explicitly labelled visual references. The helper is not an API generator and needs no API key. Generate, inspect, then copy a selected finished portrait into the project. Keep originals and rejected variants separate; only final approved portraits become app-referenced assets.

## Asset naming and compatibility handoff

New paired files:

```text
public/avatars/sport/{sport}_{tier}_male_v2.png
public/avatars/sport/{sport}_{tier}_female_v2.png
```

For example: `public/avatars/sport/football_bronze_female_v2.png`. The UI asset URL omits `public`. Preserve all existing `{sport}_{tier}.png` files as the legacy edition; do not overwrite the original rugby, football or cricket assets.

Future integration must:

- Keep the logical unlock/claim key `sport_avatar_{sport}_{tier}` unchanged. Both appearances belong to that one reward. A variant is a cosmetic choice, not a new XP-paying reward ID.
- Keep the selected logical avatar ID and its accumulated identity statistics stable when changing appearance. A male/female swap must not reset selection history or issue duplicate XP.
- Add a per-profile cosmetic presentation preference, separate from account identity. Suggested optional plan metadata is `sportAvatarAppearance: { edition: "paired_v2", variant: "male" | "female" }`; validate it and retain the legacy edition when no preference exists. This is a proposed contract, not an implemented field.
- Do not infer appearance from a person's name, age or account sex. Both options are open to every user. The collection toggle previews choices; an explicit Use action equips the chosen appearance. Previewing alone should not change the header.
- Retain an already equipped legacy portrait until the user explicitly chooses a paired appearance. This particularly matters for the mixed male/female first rugby batch. Do not silently turn an existing selected female portrait into male.
- Make header, dashboard, avatar details and permitted group identity views resolve the same edition/variant. Keep existing group-stat privacy limits.
- Publish a paired sport only when all 16 portrait files and metadata are complete. A partially produced sport stays on its existing legacy collection, or coming-soon state if there is no legacy artwork. Do not create broken previews or hide existing earned rewards.
- Preserve all current session thresholds, XP values, reward keys and server reward-map parity. This artwork work does not alter sport recognition, XP packs, badge prestige or stars.
- Build an accessible Male/Female segmented control with visible selected state, keyboard operation and comfortable narrow-mobile targets. It should take little space and load the other variant only when needed rather than eagerly downloading 208 portraits.

## Acceptance checklist and progress recording

For each image, check: correct sport/tier/variant; corresponding character face/hair/skin; equal prestige between variants; planned kit and exact award count; plausible hands and sport equipment; no unexpected text/logos; full required framing; clean transparency; readable at the current approximately 88 px gallery size; exact final filename. Compare Bronze vs Champion and Champion vs Unreal for a meaningful difference beyond colour.

For each released sport, check all 16 assets, both toggle paths, claiming only once, changing appearance without XP/stat resets, existing legacy selection, group/header/details agreement, and narrow-mobile layout. Apply these to each newly released collection; Football's recorded validation is in `football-paired-release.md`.

Keep `docs/avatar-production/production-status.json` current as each final portrait passes review. Football's sixteen slots are `ready`; the other 192 slots currently remain `not_started`. A legacy image or an unreviewed generator output is not automatically `approved`. Record the final path and any user-requested revisions so production can resume after a usage reset without repeating work.

These references ground the named football, rugby, cricket and outdoor-rowing award inspirations. They do not establish the designed tier ordering or claim those competitions were actually won by the user.
